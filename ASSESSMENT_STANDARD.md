# Assessment Standard

The academy uses five recurring assessment modes.

## 1. Explanation / prediction
The learner explains causes, tradeoffs, or expected behavior. Avoid trivia-heavy testing.

## 2. Reconstruction
Close the lesson and rebuild the key mechanism from an empty or minimal starting point.

## 3. Debugging
Repair a deliberately broken implementation or system. The learner should diagnose before changing code.

## 4. Transfer
Apply the same underlying concept to a surface problem that was not used in the lesson.

## 5. Integrated gate / boss fight
A realistic, under-specified problem that combines multiple competencies and includes traps, failures, or tradeoffs.

## Passing
A gate passes only when all critical competencies pass. A weak sub-skill triggers targeted remediation, not automatic repetition of an entire phase.

## Remediation loop
1. Identify the weak competency.
2. Give a short targeted explanation or reference.
3. Assign 1–3 focused exercises.
4. Assign one debugging or transfer task.
5. Re-test only the failed competency.

## Assistance labels
- **Closed-assistance:** no generated solution code or answer generation.
- **Docs-allowed:** official docs/search allowed, generated solutions not allowed.
- **Open-tool:** AI/tools allowed; evaluation focuses on engineering judgment, verification, and ownership.
