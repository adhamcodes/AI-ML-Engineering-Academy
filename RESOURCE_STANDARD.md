# Resource Standard

Resources serve the curriculum; the curriculum does not serve the resources.

## Resource roles
- **PRIMARY:** the main learning source for the module.
- **PRACTICE:** exercises, labs, notebooks, or problem sets.
- **REFERENCE:** official documentation or authoritative material to consult as needed.
- **OPTIONAL DEEP DIVE:** extra depth for specialization or curiosity.

A normal module should not require a giant resource list.

## Every resource record should include
- Title
- Author/provider
- Official URL
- Exact chapter/section/course unit when possible
- Why it is assigned
- What to focus on
- What can be skipped for now
- Freshness class

## Freshness classes
- **DURABLE:** mathematics, algorithms, core protocols, enduring theory.
- **REVIEW YEARLY:** libraries, APIs, deployment tools, platform practices.
- **FAST-MOVING:** agent frameworks, model APIs, tooling conventions, vendor-specific workflows.

Nothing essential should require a paid purchase. Paid resources may appear only as optional alternatives/deep dives.
