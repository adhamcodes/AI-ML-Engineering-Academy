# Start Here — AI/ML Engineering Academy

You do **not** need to read this repository from top to bottom. Follow this sequence.

## 1. Understand the rules (20–30 minutes)

Read:

- [How to Use This Academy](HOW-TO-USE.md)
- [Self-Study Operating System](SELF_STUDY_SYSTEM.md)
- [Parallel Study & Prerequisite Gates](PARALLEL_STUDY.md)
- [AI Assistance Policy](AI_ASSISTANCE_POLICY.md)
- [Roadmap](ROADMAP.md) — scan it; do not memorize it

Keep [LAB_MAP.md](LAB_MAP.md) bookmarked. It maps every phase to its controlled executable lab.

The maintainer standards (`CONSTITUTION.md`, `TEACHING_STANDARD.md`, etc.) are reference material. You do not need to study them before beginning.

## 2. Create your personal learning workspace

Keep the canonical curriculum clean. Put your notes, code, completed lab copies, assessment evidence, and progress in your **own repository or folder**. Copy [PROGRESS_TEMPLATE.md](PROGRESS_TEMPLATE.md) there.

Recommended evidence structure:

```text
my-ai-ml-learning/
├── progress.md
├── notes/
├── exercises/
├── projects/
└── assessments/
```

## 3. Begin Phase 0

Open **[00-orientation/README.md](00-orientation/README.md)** and follow it in order. Take the diagnostic honestly. Familiar-looking topic names are not proof of mastery.

When a phase reaches its build/debug work, open the matching controlled lab in **[LAB_MAP.md](LAB_MAP.md)**. Work on a copy in your own learning repository; do not put assessment solutions into the canonical academy.

## 4. Use this loop for every module

**learn → explain → predict → practice → debug → build → transfer → assess → repair**

If you get stuck, use the escalation order in [SELF_STUDY_SYSTEM.md](SELF_STUDY_SYSTEM.md) rather than disappearing into random tutorials.

If a module links several resources, use the assigned **Primary** resource first. Do not consume every optional resource.

## 5. Pass the gate before advancing

A phase is complete when you can perform its required capabilities—not when you finished watching/reading material. If a gate exposes one weak competency, repair that competency and retest it rather than restarting the entire phase.

If a software-engineering prerequisite is missing, follow [PARALLEL_STUDY.md](PARALLEL_STUDY.md) and repair it before hiding the gap behind generated code.

## Core rule

If you cannot explain a result, reproduce it, debug a failure, or apply the idea in a different context, treat the topic as unfinished.
